# Vow — serious relationship app prototype

Веб-прототип приложения для знакомств с намерением построить долгосрочные отношения или семью. Интерфейс адаптирован для мобильных экранов и desktop.

## Статус проекта

**Это проверяемый гибридный прототип, не production-сервис.** Основные API регистрации, профиля, теста ценностей, серверного поиска, симпатий, совпадений, сообщений, жалоб и блокировок реализованы и покрыты тестами. Серверная выдача отделена от демо-превью, поэтому зарегистрированные анкеты не смешиваются с макетными карточками.

## Что реализовано

- Регистрация и вход по email, выход и проверка сессии; пароли хешируются через scrypt, сервер хранит хеш сессионного токена.
- HttpOnly cookie, SameSite=Lax, Origin-check для изменяющих запросов и rate limiting на auth endpoints.
- Проверка 18+ при регистрации.
- Редактирование собственной анкеты: имя, био, страна, город, профессия, образование, языки, цель отношений, видимость.
- Загрузка JPEG/PNG-фотографий через серверную обработку с удалением метаданных, приватной выдачей и ручным одобрением. Фото не подтверждает личность.
- Серверный поиск активных видимых анкет противоположного пола с фильтрами страны, города, возраста и цели отношений.
- Тест ценностей версии 2 по 15 темам: цель отношений, дети, финансы, образ жизни, подарки, быт, верность, конфликты и честность.
- Финансовый фильтр, сравнивающий заявленные ожидания по финансовой модели, образу жизни и подаркам.
- Лайки и создание совпадения только при взаимной симпатии.
- Сообщения только между участниками активного совпадения.
- Жалобы на анкеты, блокировка и разблокировка пользователей. Блокировка исключает анкеты из поиска, удаляет лайки в обе стороны и закрывает активное совпадение.
- Отдельный демо-режим для тестирования визуальной свайп-ленты; демо-карточки явно помечаются и не выдаются за реальных людей.
- Демонстрационный каталог услуг для пары: юристы/адвокаты, аренда свадебных платьев, фотографы/видеографы, ведущие, площадки и специалисты по свадебному образу.

## Финансовая совместимость без ярлыков

Приложение не ставит человеку метку «меркантильный/меркантильная» на основании пола, дохода, подарков или желания, чтобы партнёр обеспечивал семью. Оно сравнивает три прямо заявленных предпочтения:
- финансовая модель семьи;
- ожидания от уровня расходов и образа жизни;
- значение подарков и материальных знаков внимания.

Индекс — ориентир для разговора, а не оценка порядочности или научный прогноз успеха отношений. При установленном пороге неответившие на тест анкеты не проходят финансовый фильтр. Ответы другого человека не раскрываются в поиске — возвращается только рассчитанный индекс совпадения.

## Семья, дети и честность анкеты

- Цель «Семья без регистрации брака» и отдельный формат семьи: официальный брак, совместная жизнь без регистрации или открытость обоим вариантам.
- При регистрации каждый пользователь обязан прямо указать, есть ли у него дети. Также можно указать отношение к детям в будущем и формат проживания детей. Анкеты без подтверждённого ответа не показываются в поиске.
- Для существующих аккаунтов миграция скрывает анкету до подтверждения статуса детей и выдаёт женщинам 24-часовой переходный пробный период.
- В поиске есть фильтры по возрасту, стране, городу, формату семьи и наличию детей. Карточка показывает только заявленные факты, а не догадки системы.
- Добавлены причины жалоб «сокрытие наличия детей» и «повторная анкета». Модератор/администратор может после проверки доказательств приостановить аккаунт: сессии удаляются, анкета скрывается, активные совпадения блокируются. Одной жалобы недостаточно для автоматического бана.
- Расширенный тест версии 2 дополнительно спрашивает о восстановлении доверия, безопасных границах в конфликте, раскрытии долгов до общих обязательств, привычках образа жизни, готовности к переезду и обязанностях по уходу за близкими. Ответы приватны; индекс отражает совместимость заявленных ожиданий, а не диагноз или доказательство честности.

## Доступ и подписка

- Для женских аккаунтов сервер устанавливает бесплатный доступ на первые 24 часа с момента регистрации; существующим аккаунтам предоставляется переходный день при применении миграции.
- После окончания trial сервер автоматически включает ограничение функций подбора, симпатий, совпадений, сообщений и теста, если нет активного Premium. Мужские аккаунты остаются бесплатными. Жалобы, блокировка и управление аккаунтом не закрываются paywall.
- Это автоматическое включение paywall, **не автоматическое списание денег**. Платёжный провайдер и подтверждённое согласие на оплату ещё не подключены; в API явно возвращается `paymentConfigured: false`. Для реального запуска надо интегрировать платёжную систему и вебхуки, управление отменой и возвратами.

## Дубликаты и модерация

- Добавлено удаление аккаунта с подтверждением пароля: профиль скрывается и обезличивается, сессии и симпатии удаляются, отправленные сообщения автора помечаются удалёнными, активные совпадения закрываются. Некоторые записи могут сохраняться для рассмотрения жалоб и юридических обязательств.
- Email уникален и нормализуется сервером. Миграция добавляет уникальность подтверждённого телефонного номера, а повторные анкеты можно отправлять на проверку модератору.
- Полноценное автоматическое предотвращение повторной регистрации одного человека нельзя честно обещать без верификации телефона/личности. SMS-провайдер и проверка документов ещё не подключены. IP-адрес сам по себе не используется как доказательство дубликата, чтобы не блокировать членов одной семьи или людей из общего Wi-Fi.
- Роль `moderator` или `admin` назначается доверенным администратором вне публичной регистрации. Модераторский endpoint не доступен обычным пользователям.

## Технологии

- Frontend: React, TypeScript, Vite.
- Backend: Node.js, Express.
- База данных: PostgreSQL.
- Миграции: `server/migrations/*.sql`, применяются через `npm run db:migrate`.

## Контейнерный запуск и локальное превью

Для быстрого запуска интерфейса, API и PostgreSQL через Docker Compose см. [инструкцию по развёртыванию](./docs/DEPLOYMENT.md).

Краткий порядок:
1. Создайте локальный `.env` с `POSTGRES_PASSWORD`, `APP_ORIGIN=http://localhost:8080`, `APP_URL=http://localhost:8080` и `WEB_BIND=127.0.0.1:8080`.
2. Запустите `docker compose up --build -d`.
3. Откройте `http://localhost:8080`; диагностика: `docker compose ps` и `docker compose logs --tail=100 api`.

Если почтовый провайдер ещё не настроен, подтверждение email можно отключить только для локальной проверки через `EMAIL_VERIFICATION_REQUIRED=false`. Не используйте такое значение на публичном сервере. Этот запуск создаёт локальное превью, а не публичный сайт.

## Локальный запуск

Требуется Node.js 22 или совместимая актуальная версия и PostgreSQL.

1. Установите зависимости: `npm install`.
2. Скопируйте `.env.example` в `.env`, задайте `DATABASE_URL` и остальные параметры.
3. Примените миграции: `npm run db:migrate`.
4. В одном терминале запустите API: `npm run dev:api`.
5. В другом терминале запустите интерфейс: `npm run dev`. Vite проксирует `/api` на порт 3001.

Проверка API: `GET /api/health`. Проверка БД: `GET /api/ready`. В production обязательно настройте `APP_ORIGIN`, TLS, секреты и параметры PostgreSQL.

## Основные API

- `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
- `GET/PATCH /api/profiles/me`
- `GET /api/profiles/search?country=Грузия&city=Тбилиси&minAge=25&maxAge=40`
- `GET/PUT/DELETE /api/assessment`
- `POST/DELETE /api/likes/:targetId`
- `POST /api/passes/:targetId`, `POST /api/passes/undo`, `POST /api/discovery/undo` — пропуск и отмена последнего серверного действия, в том числе после перезагрузки страницы
- `GET /api/matches`, `GET/POST /api/matches/:matchId/messages`
- `GET /api/blocks`, `POST/DELETE /api/blocks/:targetId`
- `POST /api/reports`

Для финансового фильтра можно добавить `minFinancialAlignment=67`; оба пользователя должны пройти тест. Также поддерживаются `intent`, `limit` и `offset`. Сервер сам проверяет авторизацию, доступ к совпадению и допустимость значений.

## Серверный пропуск анкет

- Добавлена таблица `profile_passes` и endpoint `POST /api/passes/:targetId`.
- Пропущенные анкеты исключаются из дальнейшего серверного поиска и не появляются снова после обновления страницы.
- В серверном поиске добавлен режим по одной анкете: свайп вправо отправляет симпатию, свайп влево пропускает анкету; доступны и кнопки. Пропуск сохраняется в БД и исключает анкету из последующей выдачи.

## Приватная автоматическая проверка (local-first)

- `server/privacyScreening.js` проверяет текст анкет и сообщений на наблюдаемые признаки: подозрительные финансовые просьбы, ссылки, публикацию контактов, повторяющийся текст и противоречия между явно указанными полями анкеты.
- Результаты сохраняются в `user_safety_screenings`: только коды флагов, серьёзность, тип проверки и статус модерации. Исходный текст и его хеши в эту таблицу не записываются.
- По умолчанию работают детерминированные локальные правила; они не требуют API-ключей, интернета или оплаты. Высокий уровень риска создаёт запись для проверки модератором, но сам по себе не приводит к автоматическому бану.
- Опционально можно установить Ollama и загрузить бесплатную модель локально на том же сервере. Включение: `LOCAL_AI_ENABLED=true`, модель задаётся через `LOCAL_AI_MODEL=qwen2.5:3b`. Вызовы модели жёстко направлены на `127.0.0.1:11434`; в настройках приложения нет поля для удалённого ИИ endpoint. Если Ollama недоступен, система использует локальные правила.
- Модель локальна только при корректном развёртывании: сервер, Ollama, резервные копии и системная телеметрия должны находиться под вашим контролем. Не включайте внешние прокси/туннели к Ollama и ограничьте порт loopback. Внешние проверки достоверности личности/документов не могут быть выполнены без соответствующего источника данных и законного основания.
- Автоматическая проверка не определяет, «врёт» ли человек, не проверяет биографические факты из интернета и не должна делать выводы о честности, родительстве, характере или доходе по полу, фото либо косвенным признакам. Для спорных случаев нужна проверка человеком.
- CI включает `server/privacyScreening.test.js`.

## Партнёры и каталог услуг

Для бизнеса доступна форма заявки на экране подбора: кафе, фотографы и другие поставщики могут оставить контакты, город и описание услуг. Заявки хранятся отдельно и доступны модераторам; решения записываются в журнал. Одобрение сейчас запускает только дальнейшую ручную проверку — публичные карточки поставщиков, бронирование, реферальные ссылки и комиссии ещё не реализованы. Не отправляйте документы через эту форму. План и этапы подключения описаны в [руководстве для партнёров](./docs/PARTNER_ONBOARDING_RU.md).

## Партнёрские услуги после взаимной совместимости

Каталог в чате пары остаётся демонстрационным: нет реальных поставщиков, заявок, документов, бронирований, цен и платежей. Перед публикацией юридических специалистов необходимо проверять личность, образование, лицензию/статус адвоката там, где это требуется, и официальные реестры по соответствующей юрисдикции. Продвижение за деньги должно быть явно маркировано и не должно влиять на статус проверки квалификации.

## Ограничения до публичного запуска

- Демо-свайп-лента и серверный поиск пока остаются отдельными интерфейсами; единая карточка и полностью унифицированный пользовательский сценарий ещё требуют работы.
- Загрузка и ручная модерация фотографий реализованы позже в этой ветке; внешние URL теперь запрещены и очищаются миграцией. До production остаются обязательными проверка реального хранения, тестирование резервного восстановления и отдельная проверка AI-модерации/антивирусного сканирования.
- Подтверждение email и восстановление пароля реализованы в коде, но требуют настройки и проверки реального email-провайдера. Real-time доставка сообщений и реальные платежи/серверная монетизация не включены в production.
- Нет законченного рабочего процесса ручной проверки личности, биометрической проверки, модерации поставщиков и админ-панели.
- Общие счётчики rate limiting хранятся в PostgreSQL; в production необходимо проверить доступность и нагрузку базы при всплесках трафика.
- Перед production нужны security review, политика конфиденциальности, сроки хранения данных, удаление аккаунта и юридическая проверка требований каждой страны запуска.

Не загружайте реальные документы в демо-формы и не считайте тестовую анкету или фотографию подтверждением личности. Не сливайте PR в `main` до проверки CI и ревью.


## Повторный показ пропущенной анкеты и аудит

- В серверном поиске добавлена отмена последнего действия: пропуска или ещё не совпавшей симпатии, в том числе после перезагрузки страницы. Отмена возвращает анкету только если она активна, видима, с подтверждённым ответом о детях и не заблокирована; лайк нельзя отменить после создания взаимного совпадения. Уже понравившиеся и пропущенные анкеты исключаются из новых результатов. Блокировка очищает симпатии и пропуски между двумя аккаунтами, чтобы блок не оставлял устаревшие действия в истории отмены.
- Запросы на изменение данных без заголовка Origin теперь отклоняются; добавлены базовые HTTP-заголовки безопасности и ограничения частоты для лайков, пропусков, блокировок и жалоб.
- Исправлено сохранение фильтра страны в демо-состоянии.
- Результаты аудита локализации и безопасности, включая ещё не реализованные переводы, email-подтверждение, восстановление пароля и загрузку фото, описаны в docs/LOCALIZATION_SECURITY_AUDIT.md.
- Добавлена инфраструктура локализации: 48 вариантов языка в переключателе, автоопределение языка браузера, сохранение выбора, базовые переводы ключевых элементов и RTL-направление. Покрытие переводами пока частичное; экраны и письма необходимо переводить и проверять отдельно.


## Международная локализация (первый этап)

- Добавлен LocaleProvider без дополнительной runtime-зависимости: выбор языка хранится на устройстве, есть режим Auto с определением языка браузера, язык и направление текста (`dir`) выставляются в HTML-документе.
- Добавлен каталог языков для дальнейшего расширения и переключатель в главной навигации. Начальные переводы для ключевых элементов навигации и серверного поиска включают английский, русский, испанский, французский, немецкий, португальский, итальянский, турецкий, грузинский, арабский, китайский и хинди. Для недостающих строк применяется английский fallback.
- RTL-направление включается для арабского, иврита, персидского и урду. Полная RTL-проверка компонентов остаётся отдельной задачей.
- Важно: каталог содержит названия многих дополнительных языков, но это не означает, что весь интерфейс уже переведён на каждый из них. Существующие экраны регистрации, тестов, чатов, подписки, модерации и письма ещё нужно переносить на ключи перевода и профессионально проверять. Не считать текущий этап завершённой международной локализацией.


## Подтверждение email и восстановление пароля

- Добавлена миграция `008_email_verification_password_reset.sql`: одноразовые токены хранятся только в виде хеша, имеют срок действия и помечаются использованными.
- В production подтверждение email включено по умолчанию. Регистрация требует настроить `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, `EMAIL_FROM` и публичный `APP_URL` с HTTPS. Без конфигурации отправки production-регистрация безопасно не создаёт новый аккаунт.
- Добавлены API для подтверждения email, повторной отправки письма, запроса сброса пароля и завершения сброса. Ответ запроса сброса не раскрывает, существует ли email; успешная смена пароля отзывает активные сессии.
- Добавлен интерфейс перехода по ссылке подтверждения и восстановления пароля. Реальную доставку писем необходимо проверить после настройки ключа Resend и домена отправителя; в текущей среде секреты не заданы.
- Перед production необходимо проверить SPF/DKIM/DMARC для домена отправителя, ограничения провайдера, шаблоны писем и сценарии истёкших/повторно использованных ссылок.


## Как открыть превью у себя

Самый быстрый способ посмотреть интерфейс Vow — запустить frontend локально. Нужен установленный Node.js 22 или совместимая актуальная версия, Git и доступ к репозиторию.

```bash
git clone https://github.com/joker096/RedThread.git
cd RedThread
git checkout audit/brand-accessibility-filters
npm install
npm run dev
```

Откройте в браузере: **http://localhost:3000**.

> Если вы уже клонировали репозиторий, повторно выполнять `git clone` не нужно. Перейдите в папку проекта, выполните `git checkout audit/brand-accessibility-filters`, затем `git pull`, `npm install` и `npm run dev`.

### Что будет работать в этом превью

- Можно осмотреть адаптивный интерфейс и доступные демонстрационные сценарии.
- `npm run dev` запускает только frontend Vite. Это не публичный сайт: адрес localhost доступен на вашем компьютере.
- Для регистрации и входа через API, серверного поиска, сохранения анкет, лайков, совпадений, сообщений и других функций, работающих с базой, дополнительно настройте PostgreSQL и backend.

### Полный локальный запуск с backend

1. Скопируйте `.env.example` в `.env` и укажите корректный `DATABASE_URL` и необходимые параметры окружения.
2. Убедитесь, что PostgreSQL запущен и база доступна.
3. Выполните миграции:

   ```bash
   npm run db:migrate
   ```

4. В первом терминале запустите API:

   ```bash
   npm run dev:api
   ```

5. Во втором терминале запустите frontend:

   ```bash
   npm run dev
   ```

Frontend откроется на **http://localhost:3000**, API работает на порту 3001. Проверьте состояние API по адресу `http://localhost:3001/api/health`; проверка готовности базы — `http://localhost:3001/api/ready`.

Для подтверждения email в production также потребуется настроить Resend и публичный HTTPS `APP_URL`. Не публикуйте секреты из `.env` и не используйте реальные личные документы для проверки прототипа.

## Текущий статус разработки Vow

Статус ниже описывает текущее состояние репозитория `main`. Код платёжной интеграции Paddle объединён, но настройка аккаунта и сквозные тесты Sandbox отложены.

### Реализовано в текущей ветке

- Сервер отклоняет новые внешние URL фотографий: фото должны загружаться через обработчик, который декодирует и повторно кодирует изображение, удаляет метаданные и помещает файл в приватное хранилище. Миграция `014_private_photo_urls_only.sql` удаляет из существующих анкет внешние/неподтверждённые URL, которые обходили приватную выдачу и ручную модерацию.

- Загрузка фотографий JPEG/PNG с декодированием и повторным кодированием через Sharp, удалением метаданных, случайными именами, лимитом 8 МБ и ограничением 20 млн пикселей.
- Приватная выдача фотографий через авторизованный API; проверяются видимость анкеты и блокировки. Новые фото скрыты от других пользователей до ручного одобрения модератором; очередь проверки доступна в панели модерации.
- Панель модерации: очередь проверок безопасности, жалобы, очередь фото и журнал действий модераторов.
- PostgreSQL-хранилище счётчиков rate limiting, общее между экземплярами backend.
- Уведомления в базе о взаимных совпадениях и новых сообщениях; пользователь может отмечать их прочитанными.
- Интеграция Paddle Sandbox: создание checkout-транзакции, проверка подписи webhook, идемпотентная обработка событий и серверное управление Premium. Аккаунт Sandbox, тарифы/Price ID и сквозной платёжный тест ещё не настроены; боевые платежи выключены.
- Шаблон политики конфиденциальности, инструкция резервного копирования PostgreSQL и скрипт локального дампа.
- Для английского интерфейса добавлены переводы вопросов теста совместимости; ключи тестов проверяются unit-тестом.

### Частично готово

- **Локализация:** в селекторе 48 вариантов языка, но полноценный перевод всех экранов и тестов на все языки ещё не завершён. Для отсутствующих ключей используется английский fallback.
- **Фотографии:** перед публичным запуском необходимо настроить постоянное приватное хранилище, мониторинг, сроки хранения и резервное копирование фото. Реализована необязательная бесплатная предварительная проверка через локальную vision-модель Ollama (`PHOTO_AI_ENABLED=true`, `PHOTO_AI_MODEL=llava:7b`); установите модель на том же сервере. По умолчанию проверка выключена; неоднозначные результаты остаются на ручной модерации. Это не заменяет антивирусный сканер, human review или проверку безопасности модели.
- **Платежи:** используется только Paddle. Код интеграции Sandbox объединён, но настройка аккаунта, создание тарифов/Price ID и сквозная проверка оплаты отложены. До завершения проверок не включать боевые платежи; секреты хранить только в защищённом окружении.
- **Резервные копии:** скрипт готов, но расписание, off-site зашифрованное хранилище, оповещения и регулярное тестовое восстановление должны быть настроены на сервере.
- **Повторный показ анкет:** отмена последнего пропуска уже есть; нужно закончить регрессионные проверки после блокировок, изменения фильтров и повторного входа.

### Обязательные блокеры до публичного запуска

1. Настроить и проверить production HTTPS, PostgreSQL, email-провайдера, постоянное хранилище фото и секреты окружения.
2. Заполнить и юридически проверить политику конфиденциальности, условия подписки, возвраты, сроки хранения данных и локальные требования каждой страны запуска.
3. Прогнать тесты доступа и безопасности, восстановление резервной копии, тесты оплаты и полный регрессионный сценарий на развёрнутой среде.
4. Проверить результат GitHub Actions на последнем коммите и провести code review. Не объединять PR в main до успешных проверок.

Отдельный публичный preview deployment пока не настроен; инструкции локального запуска находятся выше.


## Последнее обновление интерфейса локализации

- Переведены на ключи локализации общие предупреждения о статусе прототипа, переключение между демо-превью и серверными анкетами, кнопка сброса демо и нижняя навигация мобильного интерфейса.
- Подписи демонстрационных профилей в верхней навигации также используют каталог переводов.
- Для русского языка добавлены русские подписи; для других языков без соответствующего ключа применяется английский fallback. Это промежуточный шаг, не полная локализация всех экранов.
- Основные подписи формы входа/регистрации и управления аккаунтом переведены на ключи локализации, включая удаление аккаунта и восстановление пароля.
- Серверные совпадения и сообщения получили локализуемые подписи, статусы, действия отправки/обновления и форматирование даты по текущей локали.
- Для теста совместимости локализованы заголовок, описание, сохранение ответов и основные сообщения о статусе. Тексты самих вопросов и вариантов ответа пока не вынесены в каталоги переводов.
- Варианты языка, для которых нет полноценного перевода, продолжают использовать английский fallback; наличие языка в селекторе не означает завершённую локализацию.
- Для проверки реального покрытия переводов запустите `npm run i18n:report`; отчёт показывает процент ключей каталога для каждого языка и недостающие переводы остаются явно видимыми для дальнейшей работы.
- Изменения сохранены в ветке `audit/brand-accessibility-filters`. Перед слиянием необходимо проверить зелёный GitHub Actions именно на актуальном HEAD, включая lint, тесты и production build; более ранние успешные запуски не подтверждают последние изменения.


## Ограничение запросов и журнал модерации

При настроенной PostgreSQL лимиты API используют общее хранилище счётчиков, поэтому ограничения применяются между несколькими экземплярами backend. Решения модераторов по проверкам безопасности и жалобам записываются в `moderation_audit_log`; чтение журнала доступно только ролям `admin` и `moderator`. Для production по-прежнему нужны мониторинг, проверка политики хранения журналов и постоянное приватное хранилище фотографий.


## Платежи и подписки

В `docs/PADDLE_SANDBOX.md` описана единственная поддерживаемая платёжная интеграция — Paddle Sandbox. Настройка аккаунта, создание тарифов и проверка полного цикла checkout/webhook отложены до отдельного этапа. До завершения проверки не включать боевые платежи. Не добавляйте ключи и webhook-секреты в Git; храните их только в секретах окружения. После настройки необходимо проверить подписку, продление, отмену, повторные/неупорядоченные события и правила активации Premium.


## Конфиденциальность и резервные копии

В `docs/PRIVACY_POLICY_TEMPLATE.md` находится шаблон политики, который необходимо заполнить и юридически проверить до публикации. `scripts/backup-postgres.sh` создаёт локальный дамп PostgreSQL с checksum и сроком локального хранения; расписание, внешняя зашифрованная копия, мониторинг и проверка восстановления настраиваются отдельно. Инструкции находятся в `docs/OPERATIONS_BACKUPS.md`.
