# Настройка входа через Google

Vow использует Google Identity Services для веб-входа и регистрации. Без настроенного OAuth client ID кнопка скрыта, а вход по email и паролю продолжает работать.

## Google Cloud Console

1. Создайте или выберите проект в Google Cloud Console и настройте экран согласия OAuth.
2. Создайте OAuth 2.0 client ID типа **Web application**.
3. В **Authorized JavaScript origins** добавьте точный origin production-сайта, например https://vow.example.com, и локальный origin разработки, если нужен, например http://localhost:3000.
4. Перенесите client ID веб-клиента в серверное окружение как GOOGLE_CLIENT_ID. Не добавляйте OAuth client secret: для этого потока он не требуется.
5. Перезапустите API и frontend. UI получает публичный client ID с GET /api/auth/google/config и загружает GIS-библиотеку только когда Google-вход включён.

Используйте один и тот же web client ID в Google Cloud Console и API. Не задавайте client ID другого приложения, Android-клиента или iOS-клиента.

## Как проходит вход

- Для существующего Google-аккаунта сервер валидирует Google ID token через официальную Node.js библиотеку, проверяет аудиторию и подтверждённый email, затем находит аккаунт по стабильному Google sub и создаёт обычную Vow-сессию.
- Для нового пользователя Google подтверждает email и передаёт имя для заполнения регистрации. Пользователь должен заполнить дату рождения, пол, местоположение и остальные поля анкеты, а также создать пароль.
- Если email уже используется локальным аккаунтом, Vow не связывает аккаунты автоматически. Войдите исходным способом. Самостоятельная привязка Google к существующему аккаунту пока не реализована.
- При ошибке Google вход не превращается в локальный вход и не создаёт неполный аккаунт.
- Google identity хранится отдельно от изменяемого email; удаление учётной записи удаляет связанный Google subject через внешний ключ каскадно.

## Перед запуском

- Настройте OAuth consent screen, бренд, разрешённые origins и применимые требования Google к верификации OAuth-приложения.
- Убедитесь, что HTTPS включён на production origin.
- Добавьте GOOGLE_CLIENT_ID в secret/environment settings API deployment; это публичный ID, но не помещайте в репозиторий приватные OAuth credentials.
- Проверьте вход существующего Google-пользователя, регистрацию с полным профилем, локальную регистрацию, несовпадение аудитории и отключённую конфигурацию.
- Проверьте, что политика конфиденциальности раскрывает использование Google Identity Services и категорию обрабатываемых данных.
