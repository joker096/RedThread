# Подключение Paddle и RevenueCat для Vow: регистрация продавца

Эта памятка дополняет [инструкцию по тестовой интеграции](PADDLE_SANDBOX.md). Vow сейчас — веб-приложение; нативных iOS/Android-покупок в репозитории нет. Кабинеты Paddle и RevenueCat нужно создавать и подтверждать отдельно от изменений кода.

## Сначала проверьте допустимость продукта

В заявке точно опишите Vow как приложение для знакомств и объясните, как работают подбор анкет и оценка совместимости. В правилах Paddle есть ограничение на автоматизированное принятие решений или категоризацию людей. Поскольку Vow ранжирует профили по введённым пользователями предпочтениям, до подключения live-платежей получите письменное подтверждение Paddle, что такой продукт и его функции допустимы. Не маскируйте функцию под другой тип программного продукта.

Paddle проверяет домен и сам продукт. Для домена запуска checkout обычно нужны работающий сайт с HTTPS, описание продукта, функции и цены, доступные Terms and Conditions, Refund Policy и Privacy Policy, а также контакт для поддержки. Для sole trader в условиях желательно указать юридическое имя. Sandbox можно использовать без domain approval.

## 1. Регистрация продавца в Paddle

Выбирайте **Paddle Billing**, не Paddle Classic: у Billing используются API key и client-side token; термин Vendor ID относится к Classic, а для Billing используется Seller ID. Для этой связки сервер приложения получает RevenueCat-события и проверяет подписчика в RevenueCat; секреты RevenueCat остаются на сервере. Не добавляйте Paddle API key в браузер.

При заполнении формы:

| Поле | Как заполнить |
| --- | --- |
| Business type | Выберите Individual / Sole trader, только если действительно продаёте как физлицо. Если вы зарегистрированы как ИП или компания, отвечайте по фактическому статусу и документам, которые принимает форма. |
| Business name | Укажите настоящее имя/юридические данные по подсказке кабинета. Название продукта **Vow** укажите отдельно в описании или поле бренда, если оно есть. |
| Industry | Честно укажите software / consumer software и dating. В описании укажите функции знакомств и автоматического подбора, чтобы Paddle мог оценить соответствие правилам. |
| Website | Укажите контролируемый вами рабочий HTTPS-сайт. Для live checkout отправьте каждый домен, с которого будет открываться checkout, на domain review. |
| Country | Укажите фактическое место нахождения продавца и сведения, соответствующие вашим документам. Не выбирайте Грузию только из-за банковского счёта или планов открыть ИП. |

Грузия не указана в опубликованном Paddle списке стран, где продавцам запрещено работать, но это не гарантирует одобрение конкретного продавца, продукта или способа выплат. Paddle может запросить дополнительную проверку.

## 2. Проверка личности и адреса (KYC)

Если вы регистрируетесь как физлицо или sole trader, личность подтверждаете вы. Paddle проводит проверку в кабинете или через ссылку от партнёра Sumsub. Иногда проверка проходит автоматически; при необходимости попросят государственный документ личности, подтверждение адреса, а иногда короткую проверку присутствия по видео.

Не закладывайте заранее обязательное требование «паспорт должен действовать ещё 6 месяцев» и не готовьте только один конкретный документ: опубликованные правила Paddle не устанавливают этот универсальный срок или исчерпывающий список. Загружайте документы, которые запросит ваш поток проверки, через кабинет Paddle/Sumsub. Не отправляйте паспорт или выписку в чат и Git.

Paddle пишет, что проверка личности обычно проходит быстро; если нужна ручная проверка, ориентир составляет 1–3 рабочих дня. Это оценка, а не гарантия.

## 3. Выплаты и валюта

USD — поддерживаемая валюта баланса и банковских выплат Paddle, но не единственный вариант и не безусловная рекомендация для каждого банка. Paddle перечисляет доступные валюты выплат отдельно; GEL в текущем списке локальных валют выплат отсутствует. Если грузинский банк примет перевод в USD/EUR и конвертирует его в GEL, курс, комиссии банка или SWIFT могут уменьшить сумму.

До запуска проверьте в настройках Paddle, доступен ли именно ваш способ выплаты и банк. Спросите банк о входящих международных переводах и комиссиях, а Paddle — о выплате на ваш счёт и возможной конвертации. Не считайте грузинский IBAN гарантированно поддерживаемым только потому, что он существует.

## 4. Налоговые сведения

Заполняйте налоговый раздел так, как просит Paddle для вашей фактической налоговой ситуации. Не считайте W‑8BEN обязательной формой для любого человека, который не является резидентом США: IRS описывает её как форму, которую иностранное физлицо предоставляет запрашивающему налоговому агенту/плательщику в применимых случаях. Если Paddle запросит форму, уточните её у Paddle и налогового специалиста, знакомого с вашим статусом в Грузии.

Налоговый номер ИП указывайте, если кабинет его запрашивает и он соответствует вашим регистрационным документам. Статус Paddle как Merchant of Record по налогам с продаж покупателей сам по себе не заменяет ваши собственные обязанности по декларированию дохода в стране резидентства.

## 5. Настройка RevenueCat для текущего веб-приложения

1. Создайте проект RevenueCat для Vow и настройте в нём **Web Billing** с провайдером **Paddle Billing**. Для веб-приложения не создавайте вместо этого фиктивные iOS/Android приложения.
2. Создайте каталог продуктов и цены в Paddle Sandbox, затем синхронизируйте его с RevenueCat согласно инструкции интеграции Paddle Billing.
3. Создайте entitlement `premium_access` и привяжите к нему продукты, которые открывают один и тот же набор функций Premium.
4. Создайте Offering и добавьте в него пакеты, которые приложение должно показывать. Текущая версия Vow реализует один Premium-набор; отдельные Basic / Premium / Gold можно продавать как разные пакеты только после определения и реализации разных функций. Цены `$4.99 / $9.99 / $19.99` из примера не зашиты в приложение и не являются рекомендацией по ценообразованию.
5. В серверном хранилище секретов задайте переменные из `.env.example`: публичный Web Billing API key RevenueCat с префиксом `rcb_`, секретный API key RevenueCat, webhook Authorization value, ID entitlement и `REVENUECAT_ENVIRONMENT=sandbox`. Не вставляйте секретный ключ в `VITE_*`, клиентский код, Git или чат.
6. Настройте RevenueCat webhook на `https://ВАШ_API_HOST/api/revenuecat/webhook`, передайте ровно то же значение заголовка Authorization и включите события покупок, продлений, отмен, истечения, проблем оплаты, возвратов и transfer.
7. Запустите `npm run db:migrate`, проверьте тестовое событие webhook и сценарии покупки, продления, отмены, возврата, повторной доставки и двух разных пользователей. Live-режим в текущем коде закрыт.

Подробности интеграции берите из [официальной инструкции RevenueCat для Paddle Billing](https://www.revenuecat.com/docs/web/integrations/paddle) и [Web SDK](https://www.revenuecat.com/docs/web/web-billing/web-sdk). Клиент использует только публичный ключ; API key Paddle и секретный ключ RevenueCat не должны попадать в браузер.

## 6. Если позднее появятся нативные приложения

Для iOS/Android потребуется отдельный нативный checkout через соответствующие магазины и настройка store-продуктов в RevenueCat. Не перенаправляйте всех пользователей нативного приложения на Paddle: доступность внешних ссылок и альтернативной оплаты зависит от правил платформы, региона и storefront.
