## 2. Latest work in this session

### 2.1. Didit L2 SQL NULL bypass — fixed

Migration 116 added a PostgreSQL CHECK constraint for verified Didit state. PostgreSQL CHECK accepts both TRUE and UNKNOWN; because `provider_status` is nullable, a row with `status='verified'`, live environment, a session ID, and NULL provider status could satisfy the constraint as UNKNOWN.

Changes:
- Added `server/migrations/117_didit_verified_state_check_null_safe.sql`.
- Migration 117 replaces the constraint and wraps the verified-evidence predicate in `IS TRUE`.
- Added `server/diditVerifiedStateSchema.integration.test.js` coverage that clones the production table constraints, confirms a valid Approved/live/session row is accepted, and confirms a NULL provider verdict is rejected with SQLSTATE `23514`.
- Added the integration test to the explicit `npm test` script in `package.json`.

### 2.2. L3 encrypted media — authenticate before exposing plaintext

The previous AES-256-GCM read path streamed decipher output before final tag verification. That could expose unauthenticated plaintext to a future HTTP playback consumer if ciphertext were tampered with.

Changes:
- `server/identityL3Storage.js` now reads a size-bounded encrypted object, validates its structure, verifies the complete GCM tag, and only then returns a readable plaintext stream.
- AES-GCM AAD binds ciphertext to the server-generated object UUID; copying another object's valid ciphertext under a different object key fails authentication.
- The encrypted object magic was versioned from V1 to V2 for the AAD-bound format.
- Wrong-key, ciphertext-tampering and cross-object substitution tests assert that opening the object itself rejects before a plaintext stream is returned.
- The storage primitive remains unused by production HTTP routes; these changes do not make L3 operational.

### 2.3. Didit Docker configuration and test coverage

- Sandbox defaults to `sandbox`; both Sandbox and Live key-confirmation flags default to `false`. Didit secrets are not passed to the web container.
- Extended `scripts/compose-network-policy.test.js` to assert API-only exposure and safe defaults.
